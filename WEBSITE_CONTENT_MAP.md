# Pollen Data Website Content Map

Version: 1.0  
Date: 2026-04-16  
Based on: CONTENT_DNA.md

## Purpose

This document translates the content DNA into an executable page-by-page website plan.
It defines what each page must do, what sections it must include, and which CTA each page should drive.

## Global Rules

All pages must:
- Use outcome-first messaging.
- Connect each capability to business value.
- Keep copy short, scannable, and concrete.
- Avoid generic consulting language.
- Reinforce the 3-step journey: Assessment -> Foundation -> Data Products.

Primary site CTA:
- Start Your Data Assessment

Primary CTA promise:
- Get a clear roadmap in 2-4 weeks.

---

## 1) Homepage

Page goal:
- Convert qualified visitors into assessment conversations.

Primary audience:
- Enterprise and data leadership evaluating how to fix fragmented data operations.

Core narrative:
- Problem visibility -> Clear journey -> Practical outcomes -> Action.

Required sections (in order):
1. Hero
2. Problem
3. 3-step approach
4. Use cases
5. Why Pollen Data
6. CTA

Section map:

### 1. Hero
Objective:
- Deliver positioning in first screen.

Must include:
- Headline: Turn your data into a business asset, not a cost center.
- Subheadline: Start with a Data Assessment. Scale into a modern data platform and data-driven products.
- CTA button: Start Your Data Assessment.
- Secondary CTA: See Our 3-Step Approach.

### 2. Problem
Objective:
- Make pain recognizable and urgent.

Must include these pain themes:
- Data scattered across systems.
- No clear orchestration or ownership.
- BI activity with weak business impact.
- Low trust in metrics and reporting.

### 3. 3-Step Approach
Objective:
- Show practical pathway, not abstract transformation.

Cards/blocks:
- Step 1: Data Assessment
- Step 2: Data Foundation
- Step 3: Data Products

Each step must show:
- What we do
- What business capability it unlocks
- What outcome the client gets

### 4. Use Cases
Objective:
- Make value concrete by scenario.

Include:
- Mobility/transport optimization
- Operations efficiency
- Revenue generation from data

### 5. Why Pollen Data
Objective:
- Differentiate against dashboard-first or strategy-only firms.

Must state:
- We build capabilities, not just reports.
- We execute beyond recommendations.
- We optimize for ROI and business outcomes.

### 6. CTA
Objective:
- Capture qualified leads with clear next step.

Must include:
- Promise: clear roadmap in 2-4 weeks.
- Form fields optimized for qualification (name, email, org, challenge).
- Trust microcopy.

Primary CTA:
- Start Your Data Assessment

## 2) Solutions Page

Page goal:
- Explain the full capability model and reduce ambiguity about what Pollen delivers.

Primary audience:
- Buyers who need detail before a call.

Required sections:
1. Overview of 3-step model
2. Solution A: Data Assessment
3. Solution B: Data Foundation
4. Solution C: Data Products
5. Engagement model and outcomes
6. CTA

Content requirements:
- Show deliverables and expected outcomes for each solution.
- Highlight feature status where needed (Now/Next/Later).
- Use business-value language before technical details.

CTA:
- Book an Assessment Planning Call

---

## 3) Use Cases Page

Page goal:
- Prove real-world applicability across business scenarios.

Primary audience:
- Stakeholders validating relevance to their domain.

Required sections:
1. Use case index
2. Detailed use case cards
3. Outcome metrics examples
4. Path from use case to engagement
5. CTA

Use case template:
- Business problem
- Data challenge
- Pollen approach
- Expected outcomes (efficiency, trust, revenue, speed)

Required initial use cases:
- Mobility/transport optimization
- Operations efficiency
- Revenue generation from data

CTA:
- Discuss Your Use Case

## 4) About and Trust Page

Page goal:
- Build credibility and reduce perceived engagement risk.

Primary audience:
- Executive and operational buyers who need confidence in partner quality.

Required sections:
1. Mission and positioning
2. Leadership profile and expertise
3. Delivery principles
4. Working model and collaboration style
5. CTA

Content requirements:
- Keep biography concise and relevance-driven.
- Emphasize business capability building.
- Avoid consultant-style long narrative sections.

CTA:
- Talk to a Data Strategist

## 6) Contact / Assessment Booking Page

Page goal:
- Convert intent into qualified opportunity with minimal friction.

Primary audience:
- Visitors ready for direct engagement.

Required sections:
1. Clear booking value statement
2. What happens after submission
3. Qualification form
4. Privacy and trust notice

- Name
- Work email
- Organization
- Current data challenge
- Timeline urgency (optional)

Post-submit expectation block:
- Response timeline
- What prep is needed
- What deliverable preview they receive

CTA:
- Start Your Data Assessment

## 12) Page QA Checklist

Before publishing any page:
- Does the first screen explain business value clearly?
- Is the page anchored in one clear objective?
- Are all sections mapped to approved DNA narrative?
- Is there a strong and relevant CTA?
- Are features correctly labeled as Now, Next, or Later?
- Is language specific and non-generic?
